Why it exists

Google Docs comments, for documents with state

Feedback tools treat every page as flat — notes pinned to pixels and screenshots. Interactive documents aren't flat: they have tabs, filters, views. A comment made on "Metrics, North" is meaningless anywhere else, so that's the only place LivingLink shows it.

State-aware

A comment's identity is (anchor, state): tab, region, any axis the document has. Switch views and the margin updates; a chip counts what's elsewhere.

Anchored to content

Anchors are content-addressed, not positional. Reorder, edit, regenerate the document — comments find their block again, and orphans are flagged, never misplaced.

Yours, end to end

Sync runs on an open CRDT (Yjs) against a server you own. Comments persist as plain files on your disk — no vendor, no lock-in, works offline.

How it works

Three steps to a living document

Drop the layer in

One build command splices LivingLink into any HTML artifact. The document stays a single self-contained file.

Send the link

Reviewers open the page, type a name, and comment. No accounts, no installs — identity rides the link.

Review in state

Comments appear in the exact view they were made in. Flip to Read as doc to sweep every tab in one scroll.

Dark mode, done quietly

One token flip themes the document, the rail, and the dock together. No neon, no glow — the same ink-and-paper logic with the lights off.
